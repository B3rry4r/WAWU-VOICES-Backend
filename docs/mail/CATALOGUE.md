# VOICES email catalogue (V-44)

One row per template of the owner's Voices_Email_Templates (83). Columns: id, the event that sends it (file:line) or "no such
event", account (M-a, sent by WAWU ID) or notice (M-b, sent by the VOICES API through WAWU ID's mail relay), the words changed
and why, sent or kept unsent. A template for something VOICES does not do is kept in the owner's folder and listed, not sent.

Paths: WAWU ID is `B3rry4r/wawu-id` branch `v/mail-account` (head 331d34c); VOICES API is `api/src/...` in this repo.
The A rows are written by M-a. The B to H rows are M-b's, in the same table, joined by the lead.

## Rulings that apply to every A row (12 Nov 2026, lead; sender part from the owner)

- **Sender.** VOICES mails are sent from WAWU Africa's existing setup: the same `MAIL_FROM` and the same (no) reply-to WAWU ID
  uses today, on wawuafrica.com. Designed as VOICES. `VOICES_MAIL_FROM` is an optional setting (unset means today's sender) so
  a later change needs no code. The owner's `support@usevoices.com`, `hello@` and `security@` senders and reply-to are not used.
  There is no usevoices.com DNS step.
- **Footer, every A mail.** "Need a hand? Reply to this email or write to support@usevoices.com. A real person will answer."
  became "Open Voices at usevoices.com to find your way around. Please do not reply to this email, because this address does
  not take replies." Why: mail goes from a no-reply address and no support mailbox exists. "write to support@usevoices.com" in
  the Stay safe line is gone for the same reason. The `[REGISTERED ADDRESS]` placeholder line is dropped (a placeholder cannot
  ship; the owner can add the real address, see "Owner's" in the hand-back). Footer links: the owner's /help (no such page),
  /rules, /privacy, /terms became the three pages VOICES has, `/settings/legal/rules`, `/privacy`, `/terms`.
- **Logos.** Served by WAWU ID at `https://id.wawuafrica.com/assets/voices/logo-wordmark-white.png` (the way its own header
  picture is), not usevoices.com/email-assets. `VOICES_MAIL_ASSET_URL` overrides it.
- **Who gets a VOICES mail.** A request that says `app: "voices"`, or a person whose sign-up app is `voices` (new nullable
  column `wawu_users.signup_app`) where the request names no app. Everyone else gets today's WHO MADE THIS mail, byte for byte
  (`src/mail/wmt-golden.spec.ts`).
- Every mail also goes as plain text, made from the same HTML (WAWU ID's `htmlToText`), not the owner's text/ files.
